# Day 1 — Rubric

Programme-standard weights, expanded into Day 1–specific observable criteria. `scripts/grade.mjs` scores everything except Presentation (marked by hand from the learner's `NOTES.md` note) — it prints a total out of 85 and Presentation is added on top by the trainer, out of 15, for 100 overall.

| Criterion | Weight | Full marks | Partial marks | Zero marks |
|---|---|---|---|---|
| **Functionality** | 30 | `DELETE /tasks/:id` exists, returns correctly, validates input via `util/validate.ts`, uses the error envelope, and a passing sibling test in `tests/` exercises it. `verify-setup.mjs` exits 0. | One of: validation present but envelope shape wrong; test exists but doesn't actually exercise the DELETE path; route works but `verify-setup.mjs` has a soft warning. | Route missing, route present but crashes/errors on a valid request, or no test references `DELETE /tasks/`. |
| **Tool usage** | 25 | Learner used plan mode for the Step 4 lab edit and can explain why they approved the plan; `.claude/settings.json` has real allow/deny/ask rules (not a copy-pasted stub) that were demonstrably exercised (no unexpected permission prompts during grading); headless `claude -p` command was used as specified for the assessment, not run interactively and hand-edited afterwards. | Plan mode used but no clear rationale given; settings.json present but one rule category (allow/deny/ask) is missing or trivial; unclear from `NOTES.md` whether `-p` was actually used unattended. | No evidence of plan mode use; settings.json missing, invalid, or empty; assessment output looks hand-written rather than agent-produced (e.g. doesn't match repo conventions Claude would reasonably infer). |
| **Code quality** | 20 | New route code matches existing style in `tasks.ts` (validation pattern, error handling, service-layer boundary); `npm run lint` passes with zero new warnings; no direct `src/repo/` access from the route. | Lint passes but style diverges noticeably from sibling routes (e.g. inconsistent error handling); minor duplication that a second pass would catch. | Lint fails; route bypasses the service layer and touches `src/repo/` directly; error responses don't use the shared envelope. |
| **Presentation** | 15 (hand-scored) | `NOTES.md` Assessment note is specific and evidences understanding: names the exact CLAUDE.md line(s) that mattered, describes a concrete before/after (config change, not chat correction) rather than a vague "it worked better after"; orientation-question notes from the lab are accurate summaries in the learner's own words, not pasted model output. | Note present but generic ("CLAUDE.md helped it follow conventions") without a specific example; lab notes are thin but present. | No `NOTES.md` Assessment section, or notes are copy-pasted verbatim from the Claude session rather than the learner's own summary. |
| **Best practices** | 10 | `CLAUDE.md` is concise (well under context-budget-abuse territory — roughly under 100 lines) and all four required sections carry real, specific content; `.claude/settings.json` denies at least one genuinely destructive command class and asks on at least one side-effecting one, matching the reasoning taught in Block 5. | Sections present but generic/boilerplate in one or two of the four; deny/ask rules present but oddly scoped (e.g. denies something harmless while allowing something risky). | CLAUDE.md is a wall of restated code comments or is missing required sections; settings.json rules don't reflect any real risk reasoning (e.g. blanket allow-all). |

**Scoring note for the trainer**: `scripts/grade.mjs` prints a per-criterion table with points earned out of 30/25/20/10 (Functionality, Tool usage, Code quality, Best practices — Presentation is excluded from its total) and a combined total out of 85. Add your hand-scored Presentation mark (0–15) to get the final mark out of 100. The programme pass mark is 60/100 overall; the script itself exits non-zero below 60/85 on its own scope as an early warning, but the authoritative pass/fail decision is the full 100-point total including your Presentation mark.
