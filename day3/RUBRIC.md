# Day 3 — Rubric

Programme-standard weights, expanded into Day 3–specific observable criteria. `scripts/grade.mjs` scores everything except Presentation (marked by hand from the learner's `NOTES.md` note) — it prints a total out of 85 and Presentation is added on top by the trainer, out of 15, for 100 overall.

| Criterion | Weight | Full marks | Partial marks | Zero marks |
|---|---|---|---|---|
| **Functionality** | 30 | `services/` line coverage ≥ 80%; the pagination fix holds at boundary values beyond the one case already seeded in the repo (first page, a mid-set page, and the last/partial page all return the correct records with no drops or duplicates); the money-rollup fix holds across multiple fractional-value inputs with exact results, not near-misses. | One of: coverage sits just under 80% with real tests present (not padding); one fix is solid and independently verified, the other is close but fails on an input beyond the one already in the repo (e.g. only works for the exact seeded example). | Coverage well under 80%, or coverage inflated by trivial tests that assert nothing specific; either fix still fails at a boundary case beyond the one already given; a "fix" that only special-cases the existing test's exact input. |
| **Tool usage** | 25 | Regression tests for both bugs show real boundary/edge-case enumeration — multiple distinct assertions per bug, not one copy of the pre-existing seeded test; visible evidence in the test files that the learner asked "what other input would also break this?" rather than stopping at the first passing case. | Some additional cases added for one bug but not the other; edge cases added but shallow (e.g. one extra trivial case rather than a genuine boundary). | No cases added beyond what the repo already ships; regression "tests" are copies of the original assertion with no new input explored. |
| **Code quality** | 20 | `npm run lint` passes with zero new warnings; `npx tsc --noEmit` compiles cleanly; fixes are minimal, targeted changes to the buggy logic itself rather than broad rewrites or unrelated churn to files outside the two bugs' scope. | Lint or type-check passes but the fix touches noticeably more code than the bug required, or leaves behind commented-out old logic. | Lint fails, type-check fails, or the fix is implemented as a hack (e.g. hardcoding around the specific failing test's input rather than fixing the underlying logic). | 
| **Presentation** | 15 (hand-scored) | `NOTES.md` Assessment note correctly explains what was wrong with each bug in the learner's own words (not a paraphrase of a Claude explanation pasted verbatim), states specifically what each regression test proves, and names a concrete additional case checked by hand. Lab `NOTES.md` entries (TDD failure message, code-review log) are complete and specific. | Note present but vague on one bug ("it wasn't calculating right") without naming the actual mechanism; lab notes thin but present. | No `NOTES.md` Assessment section, or the explanation is generic enough that it could apply to any bug in any codebase. |
| **Best practices** | 10 | No `.only(`/`.skip(` left in any test file; `.claude/settings.json` still valid with its deny rule intact; regression tests are genuinely capable of failing (verified by the grader's revert-check) — not tests that would pass regardless of whether the bug were present. | Settings.json intact but one test file has a stray `.skip` left from debugging; regression test passes but is only weakly discriminating (passes on most but not all reverted-fix variants the grader tries). | A `.only`/`.skip` left in committed code, silently narrowing what the graded run actually exercises; a regression test that passes even when the grader reverts the fix — i.e., a test that was never really testing the bug. |

**Scoring note for the trainer**: `scripts/grade.mjs` prints a per-criterion table with points earned out of 30/25/20/10 (Functionality, Tool usage, Code quality, Best practices — Presentation is excluded from its total) and a combined total out of 85. Add your hand-scored Presentation mark (0–15) to get the final mark out of 100. The programme pass mark is 60/100 overall; the script itself exits non-zero below 60/85 on its own scope as an early warning, but the authoritative pass/fail decision is the full 100-point total including your Presentation mark.

**Anti-cheat note**: the grader independently reverts each fix and reruns its regression check to confirm the test actually fails without the fix — matching the standard applied to every graded task in this programme. A regression test that passes with or without the underlying fix scores zero on that portion of Functionality, regardless of how the rest of the submission looks.
