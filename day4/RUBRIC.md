# Day 4 — Rubric

Programme-standard weights, expanded into Day 4–specific observable criteria. `scripts/grade.mjs` scores everything except Presentation (marked by hand from the learner's `NOTES.md` notes) — it prints a total out of 85 and Presentation is added on top by the trainer, out of 15, for 100 overall.

| Criterion | Weight | Full marks | Partial marks | Zero marks |
|---|---|---|---|---|
| **Functionality** | 30 | `.claude/commands/qa-report.md` exists with parseable frontmatter and a specific, non-generic `description`; its body references `npm test`, `npm run lint`, and `npm run build` and specifies a fixed report schema (lint/build/test status + overall verdict); `.claude/skills/api-endpoint/SKILL.md` exists with parseable frontmatter including both `name` and `description`. | One of: the command's `description` is present but generic; the body references some but not all three real commands; the schema is implied rather than explicit; the skill file exists but is missing `name` or has a thin `description`. | `qa-report.md` or `SKILL.md` missing entirely; frontmatter fails to parse (malformed YAML, missing `---` delimiters); the command body doesn't reference any real repo command (fabricated-report shape). |
| **Tool usage** | 25 | The skill's `description` is written to trigger reliably — names the concrete action (add/create/scaffold) and the concrete noun (endpoint/route), not a summary of the skill's existence; `NOTES.md` has a `## Skill Auto-Activation Test` section with an exact prompt that never names the skill and a concrete, specific piece of evidence the convention fired; `NOTES.md` has a `## QA Report Run` section with real, pasted command output. | Description is workable but vague in places (names the noun but not the action, or vice versa); auto-activation section exists but the evidence is generic ("it worked") rather than a specific quoted detail; QA report run is present but looks abbreviated or edited. | No `## Skill Auto-Activation Test` or `## QA Report Run` section in `NOTES.md`; the description is a placeholder ("Helps with endpoints," "API related tasks") that gives the model nothing concrete to match against. |
| **Code quality** | 20 | The skill's body encodes this repo's actual convention with real specifics — `util/validate.ts`, delegating to a service (not `repo/` directly), ownership checks (`userId`), the error envelope shape, and sibling tests under `tests/` — not a generic "write clean code" checklist. Scored as 4 points per specific covered. | Skill body mentions the convention in general terms but is missing two or more of the five specifics listed above. | Skill body is generic boilerplate with no repo-specific detail — it could apply to any codebase unchanged. |
| **Presentation** | 15 (hand-scored) | `NOTES.md`'s `## Assessment` note explains the specific reasoning behind the skill's `description` wording, names what had to be rewritten (if anything) to get auto-activation working, and gives one concrete, non-trivial improvement a teammate would want. | Note present but generic — describes what was built without explaining the description-wording reasoning or what changed between attempts. | No `## Assessment` section, or it reads as copy-pasted model output rather than the learner's own account. |
| **Best practices** | 10 | `qa-report.md` doesn't request unscoped `Write`/`Bash` access it doesn't need for a report-only command; `CLAUDE.md` shows evidence of progressive disclosure (unchanged is acceptable, but if trimmed, the skill still covers the removed detail); no secrets or credentials appear in any `.claude/` file. | `allowed-tools` present but broader than necessary; `CLAUDE.md` trimmed but the skill doesn't fully cover what was removed. | Command requests broad, unscoped tool access with no scoping attempt; a secret or credential-shaped string appears in a committed file. |

**Scoring note for the trainer**: `scripts/grade.mjs` prints a per-criterion table with points earned out of 30/25/20/10 (Functionality, Tool usage, Code quality, Best practices — Presentation is excluded from its total) and a combined total out of 85. Add your hand-scored Presentation mark (0–15) to get the final mark out of 100. The programme pass mark is 60/100 overall; the script itself exits non-zero below 60/85 on its own scope as an early warning, but the authoritative pass/fail decision is the full 100-point total including your Presentation mark.

**Validated against the starting state**: this grader is checked to score zero on Functionality and Tool usage and exit non-zero against Day 4's unmodified starting state (no `.claude/commands/qa-report.md`, no `.claude/skills/api-endpoint/SKILL.md` — the same "nothing built yet" starting point Day 1 shipped for `CLAUDE.md`) — if it doesn't, the grader itself is broken and its score should not be trusted.
